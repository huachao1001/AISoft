# AiInstaller 开发约定

AiInstaller 是公共件：一个通用安装器 exe，加上把清单与载荷追加到它末尾的
打包器。它会被不止一个应用复用，所有设计都要按「别的应用也会用」来审查。

应用侧只提供 `setup.ini` 与待打包文件，不写安装代码、不重新编译安装器。

## 铁律：公开头文件不得出现平台类型

`include/` 下不允许出现 `HWND`、`HKEY`、`HINSTANCE`、`MSG` 等 Windows 类型，
也不允许 `#include <windows.h>`。系统能力一律经 `AiUI` 的中性接口。

`src/os/` 是唯一可以接触操作系统的目录，与 AiUI 同样的分层。

## 不内置任何应用的私有知识

以下内容**不得**出现在本库：

- 右键菜单的 CLSID、组件名、要挂到哪些对象
- 文件类型关联的后缀表、ProgID
- 应用特有的配置项、注册表路径

它们通过 `config_abi.h` 的标准 ABI 由应用提供：应用的配置 dll 导出
`AiSetupConfigApply` / `Remove` / `IsReady` / `Version` 四个函数，清单里
`[config] module=` 指向它。安装器只按 ABI 调用，不认识具体导出名。

不要退回「函数指针钩子」或「链接期注入」：安装器是单独编出来的通用 exe，
运行期才拿到应用是谁，唯一能用的契约就是一套固定导出。

## 安装包是追加数据，不是编译期资源

安装器 exe 编一次就固定，应用的名字、文案、文件表全在追加到末尾的清单里
（布局见 `include/AiInstaller/package.h`）。因此：

- 界面只有一个通用模板，靠清单的图标与文案做品牌化；不要为某个应用加布局分支。
- 清单是 INI 文本，不引入运行时 XML 解析。
- 打包顺序必须是「改资源 → 追加载荷」：`UpdateResource` 会重排 PE 映像，
  先追加就丢数据。

## 默认路径不含盘符

`AppInfo::installSubdir` 只写子目录（如 `AISoft\AiZip`），盘符由
`pickInstallVolume()` 在运行期决定。理由：装到哪个盘是本机事实，写进代码的
`D:\` 换台机器就可能不存在。

「跳过系统盘」的判定必须用 `AiUI::DriveInfo::system`，不要自己猜盘符。

选盘只看**盘**，不看范围：`perUserInstallDir()` 与 `defaultInstallDir()` 走
同一套策略，子目录永远来自清单。**不要**把「仅当前用户」改成
`%USERPROFILE%\Programs`：用户目录必然在系统盘上，那样「不装 C 盘」会被
悄悄绕过，而静默安装固定走这个范围。

盘存在不等于装得进去：有些机器的盘根 ACL 只给管理员写权限。选盘前用
`isVolumeWritable()` 建一个探针文件确认能写，不可写就换下一个盘；非系统盘
全都不可写时才回退系统盘——只有系统盘可用时必须能用它。

## 落盘与删除的语义

- 安装失败**不回滚**已落盘的文件：留在目录里比删掉更安全，重装会覆盖。
- 卸载只删清单里登记的文件，目录里用户自己放的东西保留。
- 卸载时先撤销配置再删文件：注册表先把指向断掉，界面才不会有「点开报错」的窗口。
- 删除不掉的自身用「复制到临时目录 + 脱离式进程收尾」处理，不要原地硬删。

## 清单跟着卸载程序走，安装目录不留记录文件

卸载程序是安装器本体复制出来的一份副本，安装时把清单追加到它自己末尾
（`Package::embedManifest`），于是它本身就是一个**载荷为空的合法安装包**：
`openSelf()` 读到的就是当初装了什么。安装目录因此只有应用自己的文件加一个
`uninstall.exe`，没有用户看不懂的记录文件。

三个 `installer.*` 文件是早期版本的做法，只为卸载时清理升级前的残余而保留
名字（`readLegacyCreatedDirs` / `kLegacyScopeName`）。

改动包的布局时要同时检查这条路径：副本的 `dataSize` 只等于清单长度（载荷为
0），所以 `openSelf()` 必须跳过「文件偏移落在载荷内」这层校验，否则卸载会
忽然报「不是安装包」。

顺序也不能换：`embedManifest` 必须在上一次 `UpdateResource` 之后。改资源会
重排 PE 映像，已追加的尾巴会被丢掉。

## 安装状态记在注册表卸载项里

安装器自己的状态一律放进卸载项，不往安装目录写文件：

| 状态 | 存在哪 |
|---|---|
| 安装范围 | 卸载项写在 HKLM 还是 HKCU 即代表范围，不再另存标记 |
| 新建的目录层级 | 卸载项的 `InstallCreatedDirs`（`REG_MULTI_SZ`） |
| 装过没、装在哪 | 卸载项的 `InstallLocation` |

为什么用 `REG_MULTI_SZ` 而不是拼一个字符串：路径本身可以含逗号、分号、竖线，
任何自造分隔符都会在某个用户的路径上撞车。

`writeCreatedDirs` 必须在 `registerUninstallEntry` **之后**调用：键还不存在时
写会留下一个只有 `InstallCreatedDirs`、没有 `DisplayName` 的残项，「应用与
功能」里就多出一条空名字目。

## 防重复安装

同一个应用装两份会互相覆盖注册表项与快捷方式，卸载其中一份就把另一份的菜单
也摘了。所以配置页在 `onCreate` 里先 `queryInstalled()`：已装则把目录锁到
原位置、禁用浏览与范围选择，并提示「将覆盖升级」。

范围也要一起回到原处：装成 HKCU 却按 HKLM 再装一遍，两边各留一条卸载项，
卸载只清一边。静默安装与提权重试走同一条规则（`autoScope_`/`autoDir_` 直接
覆盖），否则会变成「文件写到旧目录、卸载项登记到另一个根键」。

`queryInstalled` 判定「装过」的条件是 `InstallLocation` 指向的目录仍然存在：
用户手工删了目录就该能重装，不该被一条僵尸记录拦住。

## 卸载程序用系统的回收站图标

卸载程序在「应用与功能」里是个条目，回收站的样子让人一眼知道那是「卸载」
而不是「打开」。图标是系统资产（随 Windows 版本、深色模式变化），所以运行时
向 shell 要，而不是给每个应用多带一份 ico：

`AiUI::setExecutableSystemIcon(exePath, SystemIcon::kRecycleBin)` 用
`SHGetStockIconInfo(SIID_RECYCLER, SHGSI_ICONLOCATION)` 找到图标所在文件与
索引，再按各档边长 `PrivateExtractIconsW` 重新提取，最后写 `RT_ICON` +
`RT_GROUP_ICON`。

**全程只用 GDI，不碰 GDI+**：这个函数在安装线程上跑，UI 线程同时在用 GDI+
绘制窗口，GDI+ 的初始化/关闭与位图缓存都是进程级单例，从别的线程去动它会让
正在绘制的窗口崩溃（实测退出码 `0xC000041D`）。

取不到图标不算安装失败：精简系统里 shell 图标服务可能不可用，留着安装器原
图标也比装不上强。

## 卸载只删登记过的东西

- **文件**：只删清单里的、`uninstall.exe`，以及旧版本遗留的三个 `installer.*`。
- **目录**：只用 `rd`（不带 `/s`）、只在为空时删。目录里用户自己放的东西必须
  留着——这是卸载语义的一部分，不要为了「删干净」改成 `rd /s`。
- **父目录**：装的时候用 `missingDirectories()` 记下哪几级是本机原先没有的，
  写进卸载项的 `InstallCreatedDirs`，卸载按记录由内到外收回。**不要**改成按
  目录名猜系统目录：`AISoft` 这类名字换个用户就可能是他自己建的。
- 升级安装时 `writeCreatedDirs` 与旧记录**合并**而不是覆盖，否则第二次安装的
  `missingDirectories()` 是空表，会把上一轮「这些目录由安装器创建」抹掉。
  旧版本写在 `installer.dirs` 里的记录也会被一起读进来合并。

## 收尾进程不能用 DETACHED_PROCESS

删不掉正在运行的自己，所以写一个 `.cmd` 交给 `cmd.exe /c` 在退出后收尾。
`launchDetached` 必须用 `CREATE_NO_WINDOW`，**不能**用 `DETACHED_PROCESS`：
后者让子进程完全没有控制台，`cmd.exe` 一件命令都不执行就退出，收尾永远不跑。

脚本内容按 UTF-8 写、开头 `chcp 65001`：`%USERPROFILE%` 可能带中文用户名，
默认代码页的 cmd 读不了。

## 静默安装默认「仅当前用户」

`--silent` 这条路上没有人能点 UAC 的「是」，选「所有用户」会让进程卡在一个
永远等不到的授权框上。默认写 HKCU，需要全机的部署由调用方显式指定。

## 静默安装装完必须退出

无人值守部署等不到人来点「完成」，停在完成页就是永远不返回。所以 `--silent`
成功、失败都不留在界面上：成功退出码 0，失败退 1。也不执行 `afterInstall`——
部署机器上没有理由弹出一个 GUI 应用。

## 卸载副本靠「没有载荷」识别

卸载程序本身就是合法安装包（本体 + 清单，载荷为空）。双击它时命令行没有
`--uninstall`，只看参数会把它当安装包弹出安装界面。所以入口按
`packaged && !package.hasPayload()` 判定卸载；`--install` 留给「从卸载副本
重装」这种极端情况。真正的安装包一定带载荷，不会误判。

## 清单命令不得写死根键与盘符

`[commands]` 里的 `path` / `args` 用 `${root}`（`HKLM` / `HKCU` 按范围）与
`${dir}`（安装目录），由 `runCommand()` 按本次请求展开。

写死 `HKLM` 会踩两个坑，实测都发生过：选「仅当前用户」或 `--silent` 时越权
写全机注册表，而卸载只清 HKCU，留下的项没人收；换台机器装到别的盘时写死
路径直接指错。清单是构建期产物，装到哪个盘、哪个范围是运行期才知道的。

`runAndWait` 与 `launchDetached` 都必须自己把裸文件名解析成完整路径：
`CreateProcessW` 的 `lpApplicationName` **不查 PATH**，传 `reg.exe` 会直接
失败。前者曾漏掉这一步，`required=0` 又把失败吞了，于是整条命令静默不执行。

## 临时文件要自己删

解出来的 logo 等临时文件必须在 `shutdownPlatform()` **之后**删：AiUI 的位图
缓存（GDI+）还锁着文件，提前删必失败。

## 注释与命名

注释、文档用中文，简洁，只说「为什么」。函数动词开头，类型名词首字母大写。
